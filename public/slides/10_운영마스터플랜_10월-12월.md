### 4-2. 옥종고 개발 플랫폼(Godot 4 vs 웹) 판단 및 지원 원칙

1. **작은 구현 확인 후 결정**: 학생이 이미 시도한 Godot 4(GDScript) 작업을 존중하여, 1차 멘토링에서 현재 화면(2분 시연)을 확인하고 **한 단원의 작은 흐름(설명 입력 → 버디 반응 변경 → JSON 개념 읽기·저장 및 재실행 복원 → 네트워크 없는 고정 응답 연결)**을 수행·설명할 수 있는지 확인한다.
2. **GDScript 우선 (C# 병행 지양)**: 웹 시연 호환성(Godot 4 공식 문서상 C# 웹 내보내기 미지원)과 디버깅 단순화를 위해 GDScript 단일 구성을 우선한다.
3. **공통 JSON 스키마 및 지원 경계**: Godot 유지 시 운영사·멘토는 **데이터 스키마(JSON), GDScript의 JSON 읽기·저장·`HTTPRequest` 호출 예시, 정적 코드 리뷰**를 지원하며, 실제 Godot 씬(`.tscn`) 연결과 대상 기기 내보내기 검증은 학생과 Godot 지원 담당 멘토가 함께 확인한다. (Godot과 웹 완성 앱 두 개를 동시에 이중 개발하지 않는다.)
4. **API 키 보호 및 고정 응답 우선**: 실제 API 키(`OpenRouter` 등)는 브라우저 코드나 Godot 배포 파일에 넣지 않는다. 초기에는 고정 응답(데모 데이터)으로 상태 저장·검증 루프를 먼저 완성하고, 실제 API 연결은 키 보관·호스팅·요금 한도·중계 서버 운영 책임이 정해진 뒤 연결한다.
