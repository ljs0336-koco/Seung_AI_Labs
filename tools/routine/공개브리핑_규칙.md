# 공개 브리핑 갱신 규칙

사업공고 루틴과 테크 브리핑 루틴은 MD 보고서를 저장한 뒤, 팀 공개 페이지용 JSON을 같은 폴더에 하나 더 저장하고 페이지를 다시 만든다.

- 공개 페이지 폴더: `<루틴 폴더>\ai-edu-briefing\` (사용자가 직접 GitHub에 올린다. 이 폴더의 HTML은 손으로 고치지 않는다)
- 만들기: `python "<루틴 폴더>\_도구\build_briefing.py"`
- JSON에는 **공개해도 되는 내용만** 넣는다: 공개 공고·기사 정보, 원문 URL, 짧은 요약. 내부 일정, 사람 이름·연락처, 사용량, 내부 판단 근거는 넣지 않는다.
- 문장은 짧게 쓴다. 제목 한 줄, 요약 한 문장(최대 두 문장). 보고서 문장을 그대로 길게 옮기지 않는다.
- URL은 보고서에 적은, 실제로 확인한 원문만 쓴다. 없으면 필드를 빼거나 빈 문자열로 둔다.

## 사업공고 JSON — `01_사업공고\YYYY-MM-DD_사업공고.json`

```json
{
  "date": "YYYY-MM-DD",
  "collected_at": "HH:MM",
  "pick": {
    "title": "가장 볼 만한 공고명(짧게)",
    "org": "기관",
    "budget": "예산 또는 지원 내용(짧게)",
    "period": "사업 기간(짧게)",
    "deadline": "YYYY-MM-DD",
    "why": "우리 팀이 내세울 점 한 문장",
    "url": "원문 URL"
  },
  "items": [
    {"fit": "상|중", "title": "", "org": "", "budget": "", "deadline": "YYYY-MM-DD", "url": ""}
  ],
  "note": "필요할 때만 한 문장(예: 이번 주 적합도 '상' 공고 없음)"
}
```

- `items`: 누적목록에서 **접수중인 적합도 상·중 공고**를 모두 넣는다(pick 제외). 하 공고는 넣지 않는다. 오늘 새로 찾은 공고만이 아니라 아직 마감 전인 공고 전체가 대상이다. 마감이 한참 남은 공고도 빼지 않는다.
- 페이지에서는 마감 14일 이내 공고가 위 목록(마감 순, 최대 5건)에, 마감이 넉넉한 공고는 아래 '마감 여유 있는 적합 공고'(적합도 상 우선, 최대 3건)에 자동으로 나뉜다.
- `pick`: 오늘 보고서의 '오늘의 한 줄' 공고. 접수중인 상·중 공고가 없으면 `null`.

## 테크 브리핑 JSON — `03_테크트렌드\YYYY-MM-DD_테크브리핑.json`

```json
{
  "date": "YYYY-MM-DD",
  "collected_at": "HH:MM",
  "period": "10/12 오후 ~ 10/13 오전",
  "headlines": [
    {
      "id": "기존 id가 있으면 유지, 없으면 URL SHA-256으로 생성",
      "issue": "아동·청소년 안전|법·규제|AI 안전|보안·권한|개인정보|공정성|책임성·투명성|사회적 영향|",
      "field": "교육|에이전트|AI 코딩|챗봇|모델|기기·로봇|산업", "title": "", "summary": "한 문장",
      "source": "매체·기관", "date": "YYYY-MM-DD", "url": "",
      "lang": "en|ko",
      "digest": ["핵심 요약 문장 1", "문장 2", "문장 3", "(최대 5)"],
      "note": "우리 팀 메모 한 문장(선택)"
    }
  ],
  "video": {"title": "", "channel": "", "date": "YYYY-MM-DD", "duration": "", "url": "유튜브 URL"},
  "briefs": [{"text": "한 줄 단신", "url": ""}]
}
```

- `headlines`: 확인된 헤드라인 3건(첫 번째가 대표). 미확인 전망·소문은 넣지 않는다.
- `digest`: 페이지의 '요약 읽기' 창에 보이는 우리말 핵심 요약. 원문을 실제로 읽고 3~5문장으로 쓴다. 누가·무엇을·언제·숫자·조건·한계(자체 평가, 미검증 등) 순으로 사실만 쓰고, 원문 문장을 번역해 길게 옮기거나 따옴표로 인용하지 않는다. 영어를 모르는 팀원도 원문을 열지 않고 이해할 수 있게 쉬운 말로 쓴다. 원문을 못 열었으면 `digest`를 빼고 보고서에 이유를 적는다.
- `lang`: 원문이 영어 등 외국어면 `en`, 한국어면 `ko`.
- `note`: 우리 업무와 연결되는 점이 분명할 때만 한 문장. 공개 페이지에 보이므로 내부 사정이나 사람 이름은 쓰지 않는다.
- `video`: 링크를 확인한 영상이 없으면 `null`.
- `image`는 확인된 기존 대표 이미지 주소가 있을 때만 유지한다. 빌드·게시 도구는 원문이나 원격 이미지를 새로 요청·다운로드하지 않는다. 없으면 자체 배경을 표시한다.

## 두 축 분류와 공유 데이터 (2026-10-27)

- `field`는 기사 분야 1개, `issue`는 쟁점 0–1개다. 화면은 `쟁점 | 분야`로 표시한다. `AI 윤리`는 새 기사 태그로 쓰지 않는다.
- 쟁점은 아동·청소년 안전 → 법·규제 → AI 안전 → 보안·권한 → 개인정보 → 공정성 → 책임성·투명성 → 사회적 영향 순서로 검토한다. AI 시민성은 수업 연결의 관점으로 쓴다.
- 과거 JSON의 `tag`는 그대로 보존하며, 생성 도구에서 두 축으로 읽어 표시한다. 새 명시적 `issue`·`field`가 있으면 우선한다.
- 안정 id는 기존 `id`가 있으면 유지한다. 없으면 `n-` + `sha256(url.strip().split('#')[0].encode()).hexdigest()[:16]`이다. 제목·기사 순서·발행 날짜로 ID를 다시 만들지 않는다.
- `publish_site.py`는 전체 과거 테크 JSON의 헤드라인을 `public/content/news.json`에 모은다. 같은 id는 최신 기록을 사용한다. 공개 공유 필드는 id/title/summary/digest/source/date/url/image(선택)/issue/field이며 `note`는 제외한다.
- 기사 공유 주소는 `share/news/{id}/`이며 원문 주소와 구분한다. 원문 이미지 표시 가능, CORS 허용, 재사용 조건은 별개다. 내보내기는 자체 배경 카드가 기본이며 확인된 같은 출처 공개 자산만 선택적으로 쓴다.
- `briefing/latest.json`: date, collectedAt, headlines, bids(title/deadline/url/org), editions(date/url). 기지는 이 데이터만 읽으며 게시 도구가 JSX 날짜 문자열을 바꾸지 않는다.
- 요약 JSON·아카이브도 공개 범위를 동일하게 지킨다. 글로벌 메모리·예약 SKILL은 이 변경에 포함하지 않는다.
