# 공개 브리핑 갱신 규칙

사업공고 루틴과 테크 브리핑 루틴은 MD 보고서를 저장한 뒤, 팀 공개 페이지용 JSON을 같은 폴더에 하나 더 저장하고 페이지를 다시 만든다.

- 공개 페이지 폴더: `<루틴 폴더>\ai-edu-briefing\` (사용자가 직접 GitHub에 올린다. 이 폴더의 HTML은 손으로 고치지 않는다)
- 만들기: `python "<루틴 폴더>\_도구\build_briefing.py"`
- JSON에는 **공개해도 되는 내용만** 넣는다: 공개 공고·기사 정보, 원문 URL, 짧은 요약. 내부 일정, 사람 이름·연락처, 사용량, 내부 판단 근거는 넣지 않는다.
- 문장은 쉬운 말로 쓴다. 사업공고는 제목 한 줄, `why` 한 문장으로 짧게 쓴다. 테크 브리핑의 `summary`·`digest` 분량은 아래 테크 절을 따른다. 보고서 문장을 번역투로 길게 옮기지 않는다. 다만 보고서에 적은 사실(사례·숫자·인물)을 JSON에서 줄여 빼지 않는다(2026-11-03).
- URL은 보고서에 적은, 실제로 확인한 원문만 쓴다. 없으면 필드를 빼거나 빈 문자열로 둔다.

## 사업공고 JSON — `01_사업공고\YYYY-MM-DD_사업공고.json`

```json
{
  "date": "YYYY-MM-DD",
  "collected_at": "HH:MM",
  "pick": {
    "title": "가장 볼 만한 공고명(짧게)",
    "org": "기관",
    "budget": "예산 또는 지원 내용(짧게)",
    "period": "사업 기간(짧게)",
    "deadline": "YYYY-MM-DD",
    "why": "우리 팀이 내세울 점 한 문장",
    "url": "원문 URL"
  },
  "items": [
    {"fit": "상|중", "title": "", "org": "", "budget": "", "deadline": "YYYY-MM-DD", "url": ""}
  ],
  "note": "필요할 때만 한 문장(예: 이번 주 적합도 '상' 공고 없음)"
}
```

- `items`: 누적목록에서 **접수중인 적합도 상·중 공고**를 모두 넣는다(pick 제외). 하 공고는 넣지 않는다. 오늘 새로 찾은 공고만이 아니라 아직 마감 전인 공고 전체가 대상이다. 마감이 한참 남은 공고도 빼지 않는다.
- 페이지에서는 마감 14일 이내 공고가 위 목록(마감 순, 최대 5건)에, 마감이 넉넉한 공고는 아래 '마감 여유 있는 적합 공고'(적합도 상 우선, 최대 3건)에 자동으로 나뉜다.
- `pick`: 오늘 보고서의 '오늘의 한 줄' 공고. 접수중인 상·중 공고가 없으면 `null`.

## 테크 브리핑 JSON — `03_테크트렌드\YYYY-MM-DD_테크브리핑.json`

```json
{
  "date": "YYYY-MM-DD",
  "collected_at": "HH:MM",
  "period": "10/12 오후 ~ 10/13 오전",
  "headlines": [
    {
      "id": "기존 id가 있으면 유지, 없으면 URL SHA-256으로 생성",
      "issue": "아동·청소년 안전|법·규제|AI 안전|보안·권한|개인정보|공정성|책임성·투명성|사회적 영향|",
      "field": "교육|에이전트|AI 코딩|챗봇|모델|기기·로봇|산업", "title": "", "summary": "두 문장(80~140자, ~습니다)",
      "source": "매체·기관(원 발표·원 보도)", "date": "원문 발행일 YYYY-MM-DD", "url": "",
      "lang": "en|ko",
      "digest": ["원문에서 확인한 사실 문장 1", "문장 2", "문장 3", "문장 4", "(4~6문장)"],
      "note": "우리 팀 메모 한 문장(선택)"
    }
  ],
  "video": {"title": "", "channel": "", "date": "YYYY-MM-DD", "duration": "", "url": "유튜브 URL"},
  "briefs": [{"text": "한 줄 단신", "url": ""}]
}
```

- `headlines`: 3~4건이고, 첫 번째가 대표다. 고르는 순서와 조건은 아래와 같다(2026-11-03).
  - `collect_news.py` 후보를 묶음 ①(아동·청소년 안전·쟁점) → ②(국내 교육) → ③(해외 교육) 순으로 먼저 본다. 의미 있는 소식이 있으면 **교육 또는 아동·청소년 AI 안전 헤드라인을 1건 이상** 넣고, 대표 헤드라인도 이 중에서 먼저 고른다. 후보가 없었으면 보고서 '확인 방법'에 적는다.
  - 한 매체가 헤드라인의 절반을 넘지 않게 한다. 같은 소식은 2차 인용 매체 대신 공식 발표나 원 보도를 출처로 쓴다.
  - 헤드라인은 보도나 공식 발표여야 한다. 공식 문서의 일정 공지(모델 제공 종료·요금 변경 등)는 단신이나 보고서 시사점에 쓴다. 미확인 전망·소문은 넣지 않는다.
  - `date`는 원문 발행일이다. 미국 기사의 요일 표현('on Thursday')은 미국 날짜로 바꿔 확인한다.
- `summary`: 두 문장, 80~140자, '~습니다'체로 쓴다. 첫 문장은 무슨 일인지(누가·무엇을), 둘째 문장은 핵심 숫자·사례나 왜 중요한지를 쓴다. 공유 카드의 첫 줄로 보이므로 '~는 아닙니다', '기사에 없습니다'로 끝내지 않는다.
- `digest`: '요약 읽기' 창과 공유 페이지에 보이는 우리말 요약이다. `fetch_article.py`로 원문을 끝까지 읽고 4~6문장, '~습니다'체로 쓴다.
  - 문장마다 원문에서 확인한 새 사실을 하나 이상 담는다(누가·무엇을·언제·숫자·구체 사례·당사자 반론·다음 일정).
  - 회사 자체 주장은 '회사 발표 기준'처럼 그 문장 안에서 밝힌다. 기자의 해설과 회사·기관의 말을 구분한다.
  - 기사에 없는 것을 '없다'고 적는 문장이나, 기사 종류를 설명하는 문장('팟캐스트 소개글입니다')은 쓰지 않는다. 꼭 필요한 빈칸(아동 연령 기준, 데이터 삭제 방식 등)은 `note`나 보고서에 한 번만 적는다.
  - 원문 문장을 번역해 길게 옮기거나 따옴표로 인용하지 않는다. 영어를 모르는 팀원도 원문 없이 이해할 수 있게 쉬운 말로 쓴다.
  - 원문을 못 열면 같은 소식을 다룬 다른 기사나 공식 발표를 열고, 그것을 출처로 쓴다.
- `lang`: 원문이 영어 등 외국어면 `en`, 한국어면 `ko`.
- `note`: 우리 업무와 연결되는 점이 분명할 때만 한 문장. 공개 페이지에 보이므로 내부 사정이나 사람 이름은 쓰지 않는다.
- `video`: 링크를 확인한 영상이 없으면 `null`.
- `image`는 루틴이 넣지 않는다. `build_briefing.py`가 헤드라인마다 원문의 og:image **주소**를 읽어 채운다. 이미지 파일은 내려받지 않고, 화면에서 원문 주소로 연결하며 '이미지: 매체'를 표시한다. 못 찾으면 자체 배경을 표시한다. 같은 기사는 `image_tries`로 3번까지 다시 시도하고, 이 칸은 공개 데이터에 나가지 않는다. 빌드 출력의 '이미지 n/m'을 마지막 응답에 적는다. 이 주소는 화면 표시용이다. 공유 PNG와 메신저 미리보기(og:image)에는 쓰지 않고 자체 카드를 쓴다(2026-11-03).

## 저장 전 점검과 같은 날 재실행 (2026-11-03)

- JSON을 저장한 뒤 `python "<루틴 폴더>\_도구\check_briefing.py"`를 돌린다. [고칠 것]은 지적된 칸만 한 번 고치고 다시 돌린다. 통과하면 `build_briefing.py`를 실행한다. [확인할 것] 가운데 그대로 둔 것은 보고서 끝에 한 줄로 적는다. 전체를 다시 쓰는 반복은 하지 않는다.
- 같은 날 다시 실행하면 `_2` JSON을 만들지 않는다. 오늘 JSON에 새 소식을 합쳐 헤드라인을 3~4건으로 다시 고르고, 빠진 기사는 `briefs`로 내린다. MD 보고서에는 '추가 소식(HH:MM)' 절만 덧붙인다. 새 소식이 없으면 파일을 바꾸지 않는다.
- `briefs`는 3건이다(페이지에 3건만 보인다). '제목만 확인' 같은 단신은 넣지 않는다.

## 두 축 분류와 공유 데이터 (2026-10-27)

- `field`는 기사 분야 1개, `issue`는 쟁점 0–1개다. 화면은 `쟁점 | 분야`로 표시한다. `AI 윤리`는 새 기사 태그로 쓰지 않는다.
- 쟁점은 아동·청소년 안전 → 법·규제 → AI 안전 → 보안·권한 → 개인정보 → 공정성 → 책임성·투명성 → 사회적 영향 순서로 검토한다. AI 시민성은 수업 연결의 관점으로 쓴다.
- `issue`는 원문이 그 쟁점을 실제로 다룰 때만 붙인다. 원문에 개인정보 논의가 없으면 개인정보를 붙이지 않고, 우리 팀이 떠올린 연결은 `note`에 쓴다. 소송·법원 결정·제재·법 시행은 법·규제를 먼저 검토한다. 원문에 학교·학생·교사·학부모·아동이 나오면 `field`는 교육을 먼저 검토한다(2026-11-03).
- 과거 JSON의 `tag`는 그대로 보존하며, 생성 도구에서 두 축으로 읽어 표시한다. 새 명시적 `issue`·`field`가 있으면 우선한다.
- 안정 id는 기존 `id`가 있으면 유지한다. 없으면 `n-` + `sha256(url.strip().split('#')[0].encode()).hexdigest()[:16]`이다. 제목·기사 순서·발행 날짜로 ID를 다시 만들지 않는다.
- `publish_site.py`는 전체 과거 테크 JSON의 헤드라인을 `public/content/news.json`에 모은다. 같은 id는 최신 기록을 사용한다. 공개 공유 필드는 id/title/summary/digest/source/date/url/image(선택)/issue/field이며 `note`는 제외한다.
- 기사 공유 주소는 `share/news/{id}/`이며 원문 주소와 구분한다. 원문 이미지 표시 가능, CORS 허용, 재사용 조건은 별개다. 내보내기는 자체 배경 카드가 기본이며 확인된 같은 출처 공개 자산만 선택적으로 쓴다.
- `briefing/latest.json`: date, collectedAt, headlines, bids(title/deadline/url/org), editions(date/url). 기지는 이 데이터만 읽으며 게시 도구가 JSX 날짜 문자열을 바꾸지 않는다.
- 요약 JSON·아카이브도 공개 범위를 동일하게 지킨다. 글로벌 메모리·예약 SKILL은 이 변경에 포함하지 않는다.
